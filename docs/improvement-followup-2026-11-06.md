# GitHub経由の改善と保留事項（2026-11-06）

追跡: [#859](https://github.com/okshin-yk-private/serverlessBlog/issues/859)。
レビュー対象は develop の `057c1c0001907f8a5c78668a0d60c71402e8fd13`。
GitHub Actions の検証・デプロイ経路で反映できる修正から段階的に進める。
ローカルからの AWS 変更やローカルデプロイは実施しない。

## 第一段階

| 項目                   | 変更と検証                                                                                                                                                                                                                                       |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Plan成果物の公開範囲   | PR CIの保存済みPlan・JSON・詳細テキストをartifactやコメントに公開せず、固定ラベルと操作件数だけを公開する。機密値の有無や `sensitive` 指定に依存しない。生のPlanはrunner内でバックアップ保護検査に使い、成功・失敗時とも後続ステップで削除する。 |
| GitHubの画像キャッシュ | Astroの画像変換成果物だけを依存キャッシュから分離する。fixtures/dev/prd、OS・CPU、lockfile、Astro設定を復元キーに含め、実行ごとのキーで更新を保存する。記事データや前回のdistは復元しない。                                                      |
| 性能予算               | 既存の `validate:build` をPRビルドとGitHubのデプロイ用ビルドに接続する。gzip JS合計50 KiB・成果物合計50 MiBの既存値を維持し、超過時に成果物公開前に失敗させる。                                                                                  |

### 運用上の限界

- 件数概要は詳細Planのレビューを代替しない。値・アドレス・outputs・drift・診断内容を公開しないため、必要な詳細確認は承認されたアクセス制限付きの手段で行う。Plan失敗時の生の診断も公開しない。
- 既存のバックアップ削除・置換防止ゲートとstate lockingは維持する。今回の変更はPRコードへのAWS資格情報付与を解消するものではない。
- 過去に作成済みのartifactの削除や資格情報ローテーションはこの変更に含まれない。実際の機密値混入・取得履歴は未確認。
- 画像キャッシュは速度・費用の改善を保証しない。復元・保存時間、サイズ、ヒット率を計測し、追加保存量が効果を上回る場合は再検討する。同じURLの画像更新は配信元のキャッシュヘッダーに従う。CodeBuildのキャッシュ方式は変更しない。
- 今回の性能ゲートは成果物全体の予算であり、ページ別転送量、Lighthouse、実ユーザーのLCP/CLSの合格を意味しない。
- PRのCI、developへのマージ、DEV Deploy、mainへの反映・PRD Deployは別の状態。実施していない環境まで反映済みとは扱わない。

## 保留・後続項目

| 改善項目                               | 区分・再開条件                                                                                                                                                                                                                                                                               |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ローカル単一Lambdaビルドの失敗伝播     | **保留：ローカルデプロイ専用経路**。GitHubは全関数ビルドを使用するため今回の適用経路外。ローカルデプロイ再開前に失敗時の即終了・成果物の原子的置換を修正し、旧成果物・初回の双方で失敗を検査する。                                                                                           |
| ローカル `verify` と管理画面Lintの一致 | **保留：ローカル検証経路**。GitHub CIの管理画面Lintは既存のまま維持する。ローカル検証整備を再開する際に対象へ含める。                                                                                                                                                                        |
| Plan/Applyロール分離                   | **既存判断を維持**。[#681](https://github.com/okshin-yk-private/serverlessBlog/issues/681#issuecomment-5794882240)で「ロール管理の観点から区別しない」と判断済み。変更にはリポジトリ外のIAM・Environment設定の確認と方針変更が必要。未設定の新しいsecret名へ切り替えてCIを壊す変更はしない。 |
| Lambda関数単位の並列ビルド             | **計測待ち**。[#718](https://github.com/okshin-yk-private/serverlessBlog/issues/718)の単一ジョブ・完全一致バイナリキャッシュを維持する。並列マトリクスへの逆戻りは行わない。キャッシュミス時のビルド時間・メモリを計測してから同一runner内の並列数を判断する。                               |
| CodeBuild画像キャッシュ                | **計測・インフラ変更の後続対応**。[#685](https://github.com/okshin-yk-private/serverlessBlog/issues/685)の工程別計測を維持。GitHubのTerraformデプロイで対応可能だが、方式・保存権限・費用を確定してから別変更とする。ローカルAWS変更が必須という意味ではない。                               |
| 本文画像の最適化                       | **GitHub経由で後続対応可能**。HTML変換とサニタイズ維持、外部画像・壊れた画像・寸法・遅延読込の回帰検証を含む独立したアプリ変更として行う。                                                                                                                                                   |
| 管理画面のページ遅延読込               | **GitHub経由で後続対応可能**。ページ分割前後の初期JS量を測定し、認証・記事編集・遷移時の待機表示をE2Eで検証する。                                                                                                                                                                            |
| Astro・共有UIのLint                    | **GitHub経由で後続対応可能**。Astroパーサー等の依存追加、対象範囲、既存違反の整理を別変更にまとめる。今回の設定テストや型検査をLint済みとは扱わない。                                                                                                                                        |
| 記事一覧の分割・検索索引分離           | **計測・設計待ち**。全件検索、日付・カテゴリー絞り込み、JS無効時の一覧とURL設計を保ちながら、記事数と実測量に応じて判断する。                                                                                                                                                                |
| 厳格CSPの強制                          | **DEV受入確認待ち**。現在の実適用値を確認し、認証・画像アップロード等の受入結果と対象環境の承認後に段階的に変更する。Terraformの既定値だけで本番適用状態を断定しない。                                                                                                                       |
