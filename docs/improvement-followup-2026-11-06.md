### 運用上の限界

- 件数概要は詳細Planのレビューを代替しない。値・アドレス・outputs・drift・診断内容を公開しないため、必要な詳細確認は承認されたアクセス制限付きの手段で行う。Plan失敗時の生の診断も公開しない。
- 既存のバックアップ削除・置換防止ゲートとstate lockingは維持する。今回の変更はPRコードへのAWS資格情報付与を解消するものではない。
- 第一段階の実装範囲には過去artifactの削除や資格情報ローテーションを含めなかった。これは当時の範囲の記録であり、現在の未対応を意味しない。後続のセキュリティ対応と利用者によるローテーションとは区別する。第三者による取得・悪用の有無は断定しない。
- 画像キャッシュは速度・費用の改善を保証しない。復元・保存時間、サイズ、ヒット率を計測し、追加保存量が効果を上回る場合は再検討する。同じURLの画像更新は配信元のキャッシュヘッダーに従う。CodeBuildのキャッシュ方式は変更しない。
- 今回の性能ゲートは成果物全体の予算であり、ページ別転送量、Lighthouse、実ユーザーのLCP/CLSの合格を意味しない。
- PRのCI、developへのマージ、DEV Deploy、mainへの反映・PRD Deployは別の状態。実施していない環境まで反映済みとは扱わない。

## 後続実装（Issue #865）

本文画像、管理画面の遅延読込、Astro共通コンポーネントのLintを実装した。適用環境・PR/CI/Deployの完了状態は [Issue #865](https://github.com/okshin-yk-private/serverlessBlog/issues/865) を参照する。

- 本文HTMLは既存のGoサニタイズを前提に、HTMLパーサーで実際のimg要素だけを変換する。非画像部分は保持し、生成属性は許可リストとエスケープで制限。同一originの `/images/` のJPEG/PNG/WebPだけをWebP・複数幅へ変換する。外部画像、GIF/SVG、取得失敗は元のsrcを維持する。先頭画像がない記事の最初の本文画像はeager、それ以外はlazyとする。実寸を超える拡大はしない。
- 管理画面の各ページを遅延読込し、pathnameごとの待機表示と読込失敗時の再読み込み導線を追加した。AuthProviderの状態はページ間で維持する。
- `bun run lint` は公開Astroのページ・共通コンポーネント・TypeScript・埋込ブラウザースクリプトを検査する。既存CIの同コマンドから実行される。管理画面Lintは既存の独立設定を維持する。
- 同一のfixture環境変数とproduction buildで、entryとLoginPageの静的依存closureのJSをファイルごとgzip圧縮して合計した。変更前420,221 bytes、ページ分割後162,027 bytes（約61%減）。全JS合計は420,221→429,207 bytes（約2%増）。これは初期JSの比較であり、CSS・画像・実回線での転送量やLCP改善率ではない。最終の待機表示修正による微小なサイズ差はあり得る。
- ローカル検証: 全体verify（Lint/書式/型/ユニット/Go）成功。管理画面645件成功・5件既存skip、公開サイト457件、deploy209件、構成272件成功。本文画像の実ビルド検証4件、管理画面E2E8件成功。
- DEV画像にはBasic認証があり、Astroの画像取得が401になれば元画像へfallbackする。fixtureでの画像変換成功を本番・DEVの全画像最適化済みと読み替えない。画像変換のビルド時間・キャッシュ効果・実環境LCP/CLSは引き続き計測対象。

ローカル専用ビルド/verifyの別問題、IAM方針変更、CodeBuildキャッシュ変更、Lambda並列化、一覧・検索索引の再設計は今回も保留する。

## 計測と検査の追加（Issue #880）

実装・検証の追跡: [#880](https://github.com/okshin-yk-private/serverlessBlog/issues/880)。この節の数値はローカルproduction buildでの比較であり、DEV/PRDへの反映完了は意味しない。

1. Amplifyの検査文字列は、全JavaScriptチャンクの合計が1件であることを要求する。別々のチャンクに1件ずつ存在する重複も拒否する。文字列による検査はヒューリスティックであり、依存更新で文言が変わった場合には失敗させて再確認する。実際の重複発生を確認したという意味ではない。
2. Vite manifestからentryとLoginPageの静的依存をたどり、共有ファイルを1回だけgzip圧縮して合計する。ログインJS上限180 KiB、CSS上限190 KiBを、PRのproduction buildとデプロイ成果物のアップロード前に適用する。遅延読込される他画面・フォント・画像はこの予算に含まない。不正なmanifest、参照先の欠落、dist外の参照は失敗する。
3. 管理画面のwoff/woff2をCSSへ埋め込まず、独立ファイルとして配信する。書体・ウェイトは変更しない。同一fixture設定で共通CSSのgzipは310,558→168,233 bytes（約46%減）、ログインJSは162,615→162,616 bytes。予算は変更後の実測値に約13〜16%の余裕を持たせた回帰検出用であり、ユーザー体験の合格基準ではない。別途フォント要求が増えるため、実際の文字・キャッシュ・回線で総転送量と表示時間を測る必要がある。
4. 本文画像はrender単位で `total / registered / unsupported / fallback / skipped` をビルドログへ出力する。単位はimg要素の出現回数であり、同じ画像の重複や旧URL・canonical URLの別renderも別計上する。`registered` は変換登録の成功数で、生成ファイル数ではない。後続の生成失敗は引き続きビルド失敗となる。URL・記事名・本文・資格情報はこの統計へ含めない。

実ユーザーのLCP/CLS、画像キャッシュの費用対効果、フォントのブラウザ転送量は引き続き未計測。ローカル専用経路、AWS/IAM設定変更、CodeBuildキャッシュ、検索再設計の保留判断は維持する。

ローカル検証: Lint・書式・型検査、管理画面645件成功（既存skip 5）、公開サイト463件、deploy209件、構成282件、Goテスト成功。本文画像の実ビルド4件成功。全体verify中の構成テスト1件はYAML引用符に依存する既存テストと不要な書式変更の衝突で失敗し、書式変更を戻して構成テスト全件を再実行した。GitHub CI/DEV Deployの結果はIssue/PRで別途追跡する。

PR #881の初回セキュリティ監査で、ベースラインのGo 1.26.10に `GO-2026-6859`（net/http）を検出したため、Goの単一バージョン定義を1.26.11へ更新する。フロント改修による回帰ではないが、監査の例外追加や無効化は行わない。[Go公式リリース履歴](https://go.dev/doc/devel/release#go1.26.11) と [Go脆弱性情報](https://pkg.go.dev/vuln/GO-2026-6859)を根拠とする。到達可能という静的判定は、Lambdaでの実際の悪用成立を証明するものではない。
